## Prerendering — read this before the next release

**The prerender does not run on production.** It runs locally against a local app, and the
output ships inside the publish (`StagePrerenderedForPublish` in the csproj). There is
nothing to run on the server.

```bash
cd "NVC Claude version" && npm run build
cd ../api-dotnet && DATA_SOURCE_GALLERY=sql DATA_SOURCE_CASES=sql DATA_SOURCE_REVIEWS=sql dotnet run
# second terminal:
cd "NVC Claude version" && npm run prerender     # expect 55/55
```

Five traps, every one of which produced a successful-looking run:

1. **`DATA_SOURCE_GALLERY`, not `DATA_SOURCE_HOUSES`.** EnvConfig's own comment had the wrong
   example. Without the flag a dev machine reads Quickbase while production reads SQL, so
   snapshots freeze the wrong store's prices over the correct data. The script now compares
   the local catalogue against the live site and **refuses to run on a mismatch**.
2. **Build → start → prerender, in that order.** The app reads `index.html` once at startup;
   rebuilding while it runs leaves it serving a deleted bundle and every snapshot comes out
   empty. The script refuses rather than writing 55 blank pages.
3. **The generator will read its own output.** The server serves snapshots, so it re-saved
   the previous run — identical character counts, and a fixed URL stayed broken across two
   rebuilds. It sends `X-Prerender-Bypass: 1`. **Do not remove that header.**
4. **Restart after prerendering.** Snapshots load at startup. A stale one is why the prices
   card links looked broken after they were fixed — I hit this while verifying the fix for it.
5. **The rendered DOM has two of every meta tag** (server-injected + react-helmet). Harmless
   in a request, fatal frozen. `dedupeHead()` keeps helmet's; `<title>` is exempt because
   helmet retitles the existing element rather than adding one.

## Saved configurator links — the last table off Quickbase

`SavedConfig` entity, `ISavedConfigStore` seam, `SqlSavedConfigService`,
`SavedConfigImportService`, 15 tests. Flag: `DATA_SOURCE_SAVEDCONFIGS=sql`.

**This one has a Quickbase fallback that no other migration had.** These codes are already
in customers' inboxes. Everywhere else a bad cutover showed up as a wrong page somebody
noticed; here it is a customer clicking a link *we* sent them and getting nothing, with no
signal back. So a SQL miss falls through to Quickbase — the flag can be flipped before the
import runs, and a dead Quickbase degrades to "not found" rather than a 500.

- **Code minting checks both stores.** A code that exists only in Quickbase is invisible to a
  SQL-only uniqueness check; re-minting it would point one customer's link at another's
  configuration.
- **The importer never overwrites a code already in SQL.** After cutover those are live rows
  saved natively; a stale copy landing on one breaks a link somebody holds.

The Quickbase token expires **~Feb 2027** and fails silently. This is what removes that.

## Prices page

`/bg/ceni`, `/en/prices`, `/el/times`. Two sections — 8 box houses, 6 wagons — each with
cards then its own table. Cards link to the model's catalogue page. Verified at 375px and
1280px.

**Priced from `/api/gallery`, never from a second list.** The page's own copy of the box
prices was deleted after the 73 m² incident: the gallery said €25,500 and the configurator
catalogue said €26,500 for the same house, for weeks, and nothing could notice.
`prices.js` adds only assembly costs, keyed by **gallery id** so a title edit cannot silently
drop one.

**The two sections do opposite arithmetic:**

| | Box houses | Wagons |
|---|---|---|
| Gallery price is | the house, inc VAT | the **total**, inc VAT, assembly already inside |
| Assembly | **ADDED** (€700–€3,000 net, shown ±VAT) | **SUBTRACTED OUT** (€1,000 gross) |

Treating a wagon like a box house overstates it by €1,000. Table shapes differ (5 vs 4
columns) so a reader never has to know which rule a row follows. Pinned in `prices.test.js`.

> **Two errors worth remembering.** The first version treated house prices as net and grossed
> up the sum — charging VAT twice, overstating every total by ~€2,400. And the card links
> read `row.item.href`, which is always `undefined`, so every card fell back to `to="#"` and
> clicking did nothing; the property is **`url`**. The `'#'` fallback is what hid it — a link
> that swallows the click looks interactive and is not.

## SEO — the 14 Aug audit is closed out

- **42 product pages** were canonicalising to the homepage. Fixed at request time
  (`GallerySeoService`), because products are database rows and a build-time manifest would
  go stale the first time somebody renames one.
- **Body prerendering**: 55/55 routes, ~140k characters where every URL served 0.
  Competitors served 4,819–19,392.
- **FAQ schema declared 6 Q&As whose answers were not in the DOM.** Two causes: answers were
  unmounted when collapsed, and only the open tab's questions rendered. Both fixed.
- `Offer` schema on the prices page; the bare domain no longer a fourth homepage; sitemap
  generated from `paths.js` (it had silently never listed the services page); HSTS; a Greek
  page that canonicalised onto a 404.
- **Sitemap headers**: `sitemap.xml` was served as `text/xml` with a **7-day** cache while
  the gallery sitemap used `application/xml; charset=utf-8` and 600s. `text/xml` without a
  charset means us-ascii per RFC 3023, and a week-long cache holds a bad response for a
  week. Now matched. **Google still reports "could not be read" as of 17 Aug** — the file
  validates from outside (200 as Googlebot, well-formed, no BOM, pure ASCII, 54 locs, all
  self-referencing), so if it persists after this deploy, open the sitemap row in Search
  Console and read the specific error line.

## Admin panel

Sections: home, inquiries, leads, customers, factories, reviews, gallery, cases.

Customers hold **ЕГН/ЕИК, addresses and invoices**. Three rules for anything added here:
AdminOnly with no anonymous read path (files included); `no-store` on every response; and an
ЕГН is never a lookup key — search matches name/phone/email/ЕИК only, and the list endpoint
does not return `PersonalId` at all.

## Open, in the order I would take them

1. **Audit log.** Carried since the roadmap when the concern was "you edit live pricing".
   Sharper now: the panel holds ЕГН, ЕИК, deposits and invoices with no record of who
   changed what.
2. **Factory sheet is still `/internal/factory-sheet`, localStorage-only.** The data exists
   in exactly one browser. Doubly confusing now that a real *Factories* section sits beside
   it in the nav.
3. **`www.nvc-home4you.eu` resolves but its TLS handshake fails** — no certificate covers it,
   so anyone typing `www` gets a security warning. Add it as a custom domain with a managed
   certificate, then redirect to the apex. **Canonicalise to one hostname**; two serving
   identical content is the duplicate-content problem just removed.
4. **`dbadmin` is still the app's SQL login** — the server administrator.
5. **Documents section** — changing a brochure still needs a developer and a deploy.
6. **Managed identity for Blob** instead of a stored account key.
7. **Content**: product pages ~135 words, `/en/modular-houses` 278. The two comparison
   articles (`сглобяема къща или тухла`, `колко струва сглобяема къща`) are low-difficulty,
   high-intent, and feed the prices page.
8. Accessibility audit (EU Accessibility Act, since June 2025), Greek translation
   completeness, per-breakpoint `srcset`, PWA.
